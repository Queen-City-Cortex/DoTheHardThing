# Journeys, maps and the social card

Two checks in `npm run check:fast` (and so in CI) keep generated or hand-kept records from drifting. Neither needs a browser.

- `scripts/check-maps.mjs` (`npm run check:maps`) parses `e2e/drive.mjs` without running it. Every journey carries meta, `journey({ id, feature, proves, strings }, fn)`: the feature map that lists it, the sub-features it proves and the copy ids it asserts. The check fails when a journey has no meta, is listed in no map, in two maps or twice in one (any code span containing `vdt journey <name>` counts as a listing, such as `e2e/vdt journey <name>`), a sub-feature id is listed in two maps, a map names a journey that is gone (in a `vdt journey` line, a "see" reference, matched by its link target, or any backticked kebab-case name), a `strings` id is not in `src/copy.ts` or not asserted, or a sub-feature is proved by no journey without saying "not verified by vdt". The feature files stay hand-written: they carry the steps, clock moves and stored values a table could not. What it does not catch: a journey added outside `J` and the objects merged into it (`J.x = ...`, an alias such as `const J2 = J`, and an `Object.assign(J, x)` whose `x` is not an object literal or a top-level const holding one are reported; other ways are not; it does not compare with `node e2e/drive.mjs --list`, which imports Playwright and would add about 340 ms), prose that describes a journey without naming it, and a weak assertion: the `strings` reach check follows every helper a journey calls, so a helper that asserts a string on one branch counts. `proves` and `strings` are claims checked for existence and reach, not proof that the journey really verifies the sub-feature: a journey can list a sub-feature it never drives and the check passes.
- `scripts/check-og.mjs` (`npm run check:og`) guards `public/og-image.png`, whose words are pixels. `scripts/og/og-image.inputs.json` (outside `public/`, so it is never served) records the hashes of `scripts/og/card.mjs` and the fonts it embeds, the text of the copy ids and constants the card shows, the Pick block lengths, and the png's hash. The check fails when an input changed but the png did not, and when the png is not the recorded one; `--write` records a rebuilt card and refuses a stale one; it also refuses when there is no record, and the first record needs an explicit `--init`, so a deleted record cannot certify whatever png is there. Every `pick.*` and `tag.*` id in `src/copy.ts` is in `CARD_COPY` or in `NOT_ON_CARD` (with a reason), so a new Pick line fails until someone decides whether the card shows it. A dependency update that changes a font file fails it too, and the card then has to be rebuilt locally, since CI has no browser. The inputs are only the declared ones: a CSS or layout change on Pick does not trigger it. `--pixels` re-renders the card and compares pixels, and also checks that every line the phone shows is a declared input; it is local only, because a different Chromium build differs by thousands of pixels with the same inputs.
