# The words on screen

`src/copy.ts` is the one home of every word the app shows: the Welcome (first visit, returning morning, late start, missed days), Name, Ask, Pick (including "Nothing got a yes"), block, Close, Closed, Your days and About screens, the header, the save note, the error screen in `main.tsx`, both notifications, and the tag labels, day counts and reminder status that `logic.ts` builds. `App.tsx` and `main.tsx` render only through `t(id)`, the `fmt` templates (the lines with a value in them: the close item line, the counts, the Pick block line, the Name notes, the paused line, the reminder line, the step dots' label; `fmt` holds no sentence of its own: each one is an entry with a kind and a `{placeholder}` that `fill()` fills, and `src/copy.test.ts` fails on a literal of four or more words in `fmt`) and the constants `BRAND` and `TALK_URL`; `logic.ts` and `reminder.ts` read their words from it; the journeys in `e2e/drive.mjs` import it, so a wording change moves the app and its assertions together. A line used in two places is one entry (the hour-before-email line on the first welcome and on every morning welcome, `Back` on Name, Ask and Your days, `Yes` on Ask and Close). Some of those ids are named for one screen and show on others, so a wording change there moves every place: `close.yes` is also Ask's Yes, `pick.eyebrow` is also Ask's last button, `twoQuestions` is the last Name button and the Ask eyebrow, `yourOneThing` is the block eyebrow and the Your days stand-in for a done day with no text (rewording the eyebrow rewrites those rows), and `back`, `next`, `about`, `done`, `yourDays` and `no` each show on more than one screen. The ids, kinds and refs ship to the browser with the text (about 1.5 KB gzip); if the table keeps growing, a build-time map to text only would drop them. `SITE_URL` is the site the journeys and `scripts/verify-live.mjs` check, and `DOMAIN_DISPLAY` the domain on the link preview card (`scripts/og/card.mjs`); the meta tags in `index.html` stay literal, since the page cannot import the module, and `check-text` holds them to the same spelling. Left in code on purpose: dates through `Intl` (month and day names, a month with its year), the block-length labels (`hrs()`, such as `1½h`), and the symbols `×`, `›` and ` · ` between tags.

Each entry has a kind, like the rules in `method.ts`: `quote` (the talk word for word; `ref` is the m:ss timestamp of the transcript line where the quoted words start), `paraphrase` (the talk in the app's words, with the timestamp of the line it paraphrases) or `own` (the app's own words, which the type forbids to carry a ref). What checks it:

- `src/copy.test.ts`, everywhere: every quote and paraphrase has an m:ss ref, no own entry has one, no two ids hold the same text, and the `REQUIRED` lines (sentences only) are on their screens in every listed state, rendered with `renderToStaticMarkup`. `@ts-expect-error` lines in the test make `tsc -b` prove the type rules.
- `src/copy.test.ts`, only with the transcript: each quote is in the talk word for word, ignoring case, commas, apostrophes and spacing but not sentence ends (a quote that ends with a period must end where the talk's sentence ends, so a quote cut short fails), starting on its ref line (any of them when the talk says it more than once); each paraphrase ref is a real timestamp. **The transcript is not in the repo** (the talk is someone else's content), so these run only where `FERRISS_TRANSCRIPT` points at a transcript file, locally and not in CI, and show as skipped when none is set. A path that is set but cannot be read, or a file with no `[m:ss]` lines, is one failing test naming the path, never a skip. `scripts/transcript.mjs` is the one way both this test and `npm run check:quotes` find it.
- `eslint.config.js` (`COPY_FILES`, inside `boundaries()`): inline text of four or more words anywhere in the app files (`App.tsx`, `main.tsx`, `logic.ts`, `reminder.ts` and the other owner modules), in a screen or a module-level constant alike, is an error that says to move it to `copy.ts`. It does not see strings of one to three words, text in a file not on the list (a new file has to be added), or a sentence joined from short pieces; `scripts/boundaries.test.mjs` fails if a listed file is renamed or moved, or stops being linted.
- `scripts/check-text.mjs` (in `npm run lint` and `npm run check:fast`): no em or en dash in what a person reads, the domain shown as DoTheHardThing.app (lowercase only in a URL or a code span that is only the hostname), the brand as Do The Hard Thing.
- `scripts/check-imports.mjs` (`npm run check:imports`, in `npm run check:fast`, about 60 ms): every package the repo's own code imports (`src/`, `worker/`, `scripts/`, `e2e/`, root config files) is declared in `package.json`. `acorn` (check:maps), `js-yaml` (check:workflows) and `playwright-core` (check:og --pixels) used to arrive only through eslint's and Playwright's dependency trees; they are devDependencies now, so an eslint major that drops `@eslint/eslintrc` cannot break a guard. It reads declarations, not the lockfile, and cannot see packages used by name only (a CLI run with npx, a Vite plugin named in a string) or an import that is not first on its line.

## Open product questions

- **Q1, the late cutoff.** The Welcome screen treats opening at or after 11:00 as a late start; the Pick screen shows its late line from 12:00. Both are kept as they were. Choosing one hour means deleting the `@ts-expect-error` line in `src/method.ts` and merging `LATE_CUTOFFS` into one value.
- **A trace of the cited transcript lines.** Committing the few transcript lines the quotes cite (about 8) would let CI check the quotes too. It is the owner's call whether verbatim lines of the talk belong in a public MIT repository; until then the quote checks are local only. A committed trace would also need its own guard, since CI could not tell a hand-edited trace from the talk.
- **The hour line on a late first visit.** The first welcome shows "Ideally an hour before email or screens." at any hour, also after the 11:00 cutoff where a returning welcome drops it. It was added to the first welcome unconditionally in an earlier change; before that a late first visit had no hour line. The required-lines test keeps today's behavior (`firstWelcomeLate` in `REQUIRED`); whether it is intended is open.
